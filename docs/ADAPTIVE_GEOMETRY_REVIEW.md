# 自适应共享终端尺寸与 review

后续版本已区分浏览器页面隐藏与 Hub 内部标签隐藏；本报告的“隐藏标签让权”描述属于当时版本。当前实现与验证见 [跨设备视口修复 review](CROSS_DEVICE_VIEWPORT_REVIEW.md)。

## 问题与范围

现场只读核查发现，2225 与 2226 的 PTY 都停留在 99 列 × 20 行。旧默认 `leader/first` 保持首个客户端的尺寸；控制端隐藏后只要连接存在仍不让权，Hub 又已移除手动接管入口，导致小窗口先连接后桌面无法自动恢复。

本次同时更新 GoTTY 服务端、直连前端和 Hub 使用的 terminal-core 0.6.0。保留一个实例对应一个 PTY、所有客户端使用同一确认网格的模型。没有修改 GitHub Actions，没有添加 CI UI 测试。

## 最终行为

| 情况 | 行为 |
| --- | --- |
| 默认策略 | GoTTY 默认 `adaptive`；显式指定 `leader/fixed/median` 保持兼容 |
| 手机先连接 | 先适配手机；桌面随后打开，自动选择桌面网格 |
| 桌面正在使用 | 手机连接、刷新、横屏或缩小可视高度不抢占桌面尺寸 |
| 选择候选 | 仅可见可写且有效的客户端；精细指针及悬停优先，其次未知输入能力，最后触屏；同类按实际行列容量选择 |
| 稳定性 | 同类候选容量至少增加 20% 才替换健康控制端；候选及尺寸稳定 500ms；使用一个真实视口的完整行列数 |
| 隐藏标签 | 隐藏 2 秒后允许后备候选接管，随后仍有稳定期；短暂切换保持尺寸 |
| 页面冻结 | 支持新协议的可见客户端每 3 秒续约，15 秒过期；失焦和打开设置不视为隐藏 |
| 刷新和断线 | 同身份恢复继续使用现有 5 秒断线宽限；超过宽限后可回落至手机，桌面返回后自动恢复 |
| 没有候选 | 保持最后网格；旧客户端继续按连接与显式可见性处理，不强制要求续约 |
| 尺寸诊断 | 两端连接数提示显示共享网格、本地容量、尺寸来源及选择原因；GoTTY 新增经过现有管理认证的只读 `GET /-/terminal-state` |

`leader-select`、`leader-switch` 和手动接管只影响显式 `leader` 策略。新核心只向 `adaptive` 服务端周期续约，避免改变旧 `on_idle` 的触发方式。只读观察者不能改变尺寸，也不能参与选举。

## 整体 review

没有发现遗留阻断问题。重点检查：

- 所有选举与尺寸状态在会话锁下处理，PTY ioctl 和 VT 回放继续使用原来的有序发布路径；ioctl 失败不确认新网格。
- 不变的续约只更新有效期，不产生 PTY resize 或新的回放事件，也不会不断延后最后一次实际 resize。
- 隐藏宽限按首次隐藏计算，不随重复报告延长；冻结客户端的自动查询回复也会被排除，避免 Vim 收到重复响应。
- 定时器随终端销毁清理；隐藏页面不周期续约，认证初始化完成前不发送尺寸，旧服务端保持事件驱动行为。
- 本地测量尺寸与服务端绘制网格仍然分离，不把服务端确认尺寸回送为视口请求；工具提示不调整布局或重建连接。
- 只读诊断不创建连接、不重新选举、不写 PTY、不追加回放，不返回浏览器身份密钥、凭据或终端内容；公共分享入口不开放该管理诊断。
- Hub 包锁定文件、vendor 包与 GoTTY 源码一致；GoTTY 嵌入的 JS 与 sourcemap 已更新。

## 兼容与边界

完整行为需要同时更新 GoTTY 与 Hub；已有显式 `resize_policy = "leader"` 配置需要主动改为 `adaptive`。本次未部署到正在运行的服务。

默认 PTY 上下限继续生效（60–240 列、20–80 行）。手机跟随桌面时仍可能需要内部滚动；单 PTY 无法让同一个 Vim 同时使用两套独立网格。续约兼容旧客户端时，它们仍依赖可见性事件及连接断开，不能获得完整的冻结检测。

浏览器验证使用真实 Chromium，手机、横屏和可视高度由浏览器模拟；未在实体 iOS/Android、Safari 或 Firefox 上验收。沿用既有有界内存历史与 VT 扩展支持范围。
