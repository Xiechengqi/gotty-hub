# 跨设备终端尺寸与视口修复

## 根因与最终行为

三个现象来自两条相互放大的缺陷：服务端把 Hub 内部标签切换等同于浏览器退到后台，隐藏约 2.5 秒后把共享 PTY 交给手机；客户端又会因无实际滚动的触摸暂停跟随，隐藏光标时停止协调外层位置。桌面返回触发扩屏重绘，切走触发缩屏及浏览器滚动位置夹限，因此手机出现上移、闪动和偶尔“重新对齐”。

两个项目继续使用一个 PTY、一套已确认网格。本轮同时更新 GoTTY 服务端、直连前端和 Hub；两端共享的 terminal-core 升至 0.8.0，完整效果需要一起升级。尺寸保留用于 `adaptive`；显式配置 `leader/fixed/median` 保持旧策略，已有 `leader` 配置需主动改为 `adaptive` 才启用本轮尺寸策略。

| 场景 | 行为 |
| --- | --- |
| 桌面切换 Hub 内部标签 | 保留已有共享尺寸；前台隐藏标签续约，手机不接管，不触发两端 resize |
| 隐藏标签收到测量 | 只使用最后有效测量续约，不提交新网格；未到达 ioctl 的请求不视为已确认容量 |
| 新候选 | 必须可见、可写、有效；隐藏标签只可保留已有所有权，不能获取新所有权 |
| 大触屏与隐藏桌面 | 低优先级触屏不能因面积更大抢占健康桌面；同类候选仍遵守 20% 门槛 |
| 浏览器后台、冻结、断线 | 后台不续约，15 秒过期；断线保留现有 5 秒宽限；没有合格候选时不合成小网格 |
| 桌面首次打开手机控制的终端 | 等回放解析和实际尺寸确认后显示首个画面，避免小网格先闪现；旧服务端有 1.5 秒显示等待上限 |
| 手机实时输出 | 普通缓冲区把输入/内容行对齐本地可用底部；`clear` 和 Vim 不追逐空白屏底 |
| 持续隐藏光标重绘 | 使用最近输入位置与内容末行，首次回放也能找到内容位置 |
| 触摸边界与查看历史 | 无实际滚动不暂停；实际上翻、选择文字保留历史锚点；滚回实时处、返回按钮或本端输入恢复 |

## 整体 review

- 页面、标签与连接健康分别建模，保留旧 `visible` 及旧客户端语义。重复后台报告不能延长租约。
- 保留尺寸与终端自动查询回复分别选择客户端；隐藏桌面不回复，手机仍可作为唯一可见回复者，避免 Vim 收到重复协议数据。
- 不变网格跳过 xterm resize，避免每次状态/可见性通知引起额外重排。首次发送使用同步有效测量，未测得时不发送默认 80×24。
- 回放抑制先于快照尺寸变化。布局调整覆盖随后的动画帧滚动事件；新的真实手势可以立即接管，不吞掉用户滚动。
- 历史继续用 marker 保持内容位置，处理重排、淘汰、隐藏标签、软刷新；横向位置、原生缩放及键盘避让保留。
- 首次画面等待只影响尚未显示的渲染层；输入辅助层保持可聚焦，正常切换与软刷新不重遮蔽。等待定时器、动画帧及终端订阅随销毁清理。
- 诊断属性仅包含共享网格、来源设备类别、页面/标签可见性、跟随原因、缓冲区类型、两层滚动及 visualViewport 数值，不记录终端内容、凭据或浏览器身份。
- GoTTY 嵌入资源、Hub vendor 包和锁文件须与共享源码一致。GitHub Actions 不增加或运行 UI 测试。

Review 发现并修正：隐藏桌面与超大触屏之间的优先级漏洞；未确认容量影响同类候选比较；连接早于延迟 fit 时默认网格泄漏；工具提示消费测量、重复续约触发多余 React 渲染；把可见性/选举通知误当作尺寸确认而过早显示首个画面；隐藏标签收到全局 pointerup 时误暂停跟随；模拟触摸事件缺少完整 TouchEvent 字段。浏览器回归改用真实 Chromium 触摸输入，并更新此前仍期待 32px 的旧标签栏断言为当前 24px。无遗留阻断问题。

## 边界

一个实例仍然共享一套 PTY 网格，手机查看宽屏程序时可能需要横向滚动。真实窗口尺寸变化、浏览器后台过期或长断线仍会改变共享程序布局。隐藏光标的内容位置属于通用视口启发式，不能理解所有应用的语义。历史保留预算和 VT 扩展范围沿用原设计。

浏览器验证使用真实 Chromium 与触摸输入；手机尺寸和软键盘高度/平移由受控环境驱动。实体 iOS/Android、Safari 和 Firefox 仍需实机验收。本次未部署。
