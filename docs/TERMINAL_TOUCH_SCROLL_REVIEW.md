# 移动端终端触摸滚动修复与 review

## 问题与根因

在远程隔离实例中，手机单独打开 GoTTY，打印 250 行后仍保留约 200 行历史；原生单指拖动不能翻阅，鼠标滚轮可以。电脑和手机同时连接时，原生触摸只能移动当前共享屏幕被遮挡的区域，到顶部后无法进入更早历史。这是已保留内容无法通过触摸访问的实现 bug。

xterm 6 的历史采用虚拟滚动，不是浏览器可以原生平移的长 DOM。原 ViewportFollow 仅从触摸事件记录滚动意图，未实际驱动内部历史；外层 overflow 只能覆盖共享屏幕平移。旧测试手动设置 scrollTop 或使用鼠标滚轮，未覆盖手机独立连接时的真实触摸历史浏览。

## 实现

GoTTY 的 terminal-core 升至 0.10.0，Hub 消费同版本 vendor 包与锁文件，GoTTY 同步嵌入生产 JS 和 sourcemap。

- TouchScroll 仅接管超过方向阈值的单指纵向拖动，按帧合并位移，普通屏幕提供有界短惯性。水平手势、长按、已有选择和双指缩放继续交给原有处理。
- ViewportFollow 先分配位移到本端外层屏幕，再通过 xterm 公开接口翻阅内部历史，保留不足一行的余量。两层更新后同步保存锚点，实际离开实时位置才暂停跟随；新输出保留阅读位置，反向滚回实时位置或主动输入恢复跟随。
- 只读终端可以本地查看历史。备用屏幕无普通历史；仅在启用 VT200/drag/any 鼠标模式且 disableStdin=false 时转发滚轮，通过 xterm 自身处理协议编码，每次更新最多 8 个事件。该路径不继续惯性发送，也不注入方向键。
- 输入、布局变化、回放及缓冲区切换停止旧手势。双指加入、取消、隐藏和失焦同时清理意图；新触摸或指针操作停止惯性。销毁移除监听器和动画帧。
- 不修改共享 PTY 尺寸策略、后端协议、历史保留预算、数据库或 GitHub Actions。历史没有服务器分页和永久归档；应用已经清除的内容不能通过本次修复恢复。

## 整体 review

检查了外层/内部滚动衔接、慢速位移累计、持续输出锚点、历史淘汰与重排、输入权限、应用鼠标协议、横向手势冲突和生命周期清理。补充了取消/缩放时清理滚动意图的边界处理，未发现待修复的阻塞问题。

只读模式只禁止向应用发送输入，不禁止本地历史浏览；鼠标编码复用 xterm，不直接使用私有核心接口。用户在支持鼠标的全屏程序中拖动仍会改变共享应用状态，这是程序输入，与本地历史浏览不同。
