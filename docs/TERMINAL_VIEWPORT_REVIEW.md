# 移动端共享终端的实时视口

后续 0.8.0 核心已完善触摸边界、持续隐藏光标、首次显示与跨设备标签切换；当前实现与验证见 [跨设备视口修复 review](CROSS_DEVICE_VIEWPORT_REVIEW.md)。

## 问题和实现

电脑与手机共同打开一个终端时，小窗口保留服务端确认的完整网格。原实现只滚动 xterm 的历史缓冲区，没有协调外层像素滚动，因此手机可能只看到共享画面的上部；Hub 的绝对定位快捷键还会遮挡末尾几行。这是客户端视口协调缺陷，单 PTY 共用尺寸的模型继续保留。

`@gotty/terminal-core@0.7.0` 新增 `ViewportFollow`，Hub 和直连 GoTTY 共用：

- 在解析、渲染及布局就绪后合并到动画帧更新，按当前光标行做最小纵向滚动。`clear` 和 Vim 不会被强制滚到空白屏底，隐藏的重绘光标不拉动外层视口。
- 滚轮、触摸上翻、滚动条与文字选择暂停跟随。以 xterm marker 锚定正在看的历史内容，处理仅外层滚动、输出新增行、历史淘汰和网格重排；渲染器保留时的标签切换、软刷新和快照恢复继续保留浏览位置。
- 返回实时位置、点击“回到输入位置”、本端键盘、IME、粘贴、语音或快捷键输入恢复跟随。终端自动查询回复和传输协议回送不触发恢复。横向位置独立保留，仅本端输入或明确返回时按需露出光标。
- Hub 快捷键作为 flex 子项占用实际高度，测量结果同时用于悬浮控件避让。两端包含安全区域；视口高度与顶部平移一起处理，缩放期间保留浏览器的原生平移与缩放。
- 直连页面移除 `.xterm` 上额外的固定高度和横向 overflow，统一由 `#terminal` 承担外层像素滚动。

所有视口操作只修改当前页面的滚动、布局和本地跟随状态。适配器继续独立报告本地容量、按服务端确认网格绘制，没有修改服务端尺寸策略或通过输入请求调整尺寸。整页刷新新建视口控制器，恢复后默认跟随实时位置；不跨刷新存储终端文本或历史位置。

## Review 重点

- 光标行来自公开缓冲区信息与真实屏幕矩形，滚动不重建连接或改写终端行列数。布局变化包裹尺寸更新，避免把程序产生的滚动误识别为用户查看历史。
- 暂停跟随时同时固定内外两层滚动，避免内层仍在实时末尾、外层虽未移动但阅读内容不断上移。marker 随有界历史淘汰和列重排更新。
- 回放期间不执行跟随，解析结束后恢复浏览位置或显示实时光标；输入恢复跟随与自动协议回复分开。
- 动画帧、DOM/终端订阅、ResizeObserver、marker 和返回按钮随终端销毁清理。Hub 的账号设置、权限和焦点恢复继续走既有组件。
- “回到输入位置”按下时保留终端焦点，避免软键盘收起后按钮移动、点击丢失。隐藏标签报告的零滚动位置不会覆盖最后可见位置；历史达到上限后也通过 marker 识别淘汰，避免误判为手动滚动。
- Hub vendor、锁文件和 GoTTY 的共享核心、嵌入 JS/sourcemap 必须一致。

## 隔离验证

构建、测试及浏览器进程仅在 `ssh xianyu` 的 `/root/gotty-viewport-review.hljwer` 中运行，使用独立账号、数据库、绑定文件和回环端口。没有在本地运行应用或测试，也没有替换或重启现有 Hub 或 GoTTY。没有向 GitHub Actions 添加 UI 测试。

定向浏览器入口：

```sh
WORKSPACE_SUITE=viewport HUB_BINARY=/path/to/gotty-hub GOTTY_BINARY=/path/to/gotty \
  node tests/workspace-regressions.cjs
```

该回归检查实际屏幕和光标行的像素矩形、真实缓冲区和服务端诊断网格；覆盖电脑长屏、手机恢复/旋转、`clear`、历史阅读、新输出、切换标签、软刷新、返回按钮、输入恢复、Vim、原生缩放，以及可视区域平移与软键盘动画、快捷键占位和直连页面。

整体 review 同时修正分屏和透明度回归的计数方式：自适应协议每 3 秒携带相同行列数续约，这不代表 PTY resize。检查仍会捕获实际行列数变化，同时允许尺寸未变的续约消息，避免测试依赖执行时序。

## 边界

所有客户端仍共用一套 PTY 网格，小屏可能需要横向滚动。已有历史保留预算和 VT 快照扩展范围不变。Vim 的备用屏幕没有独立历史，程序自行改写的画面不作为历史归档；隐藏光标期间保留当前外层位置。

浏览器验证使用真实 Chromium；软键盘的高度和平移由可控 visualViewport 驱动，原生缩放由浏览器执行。实体 iOS/Android 的输入法与 Safari 行为仍需实机验收。
