## 整体 Review

对布局尺寸、菜单与拖拽事件、分屏分组、实例生命周期、设置保存、旧配置迁移及权限边界完成检查，未发现剩余阻断问题。实现中处理了以下问题：

1. 删除原手机隐藏 tab 的样式与旧布局占位，使手机和桌面共用同一等宽布局；终端容器从 `y=0` 开始，不保留最小高度或顶栏外边距。浮动终端工具下移至顶栏下方，避免按钮相互覆盖。
2. 自动打开实例时，以已知实例顺序区分“新实例”和“用户关闭的实例”。重复 SSE、普通离线及重新上线不会重新打开已关闭 tab；解绑和撤权移除相应实例及失效分组。
3. 全部实例出现 tab 后，不同时建立全部后台连接。新增延迟挂载，首次查看后保持 xterm 和 WebSocket；排序、交换、透明度变化不销毁渲染器。关闭或离线按现有生命周期释放连接。
4. 分屏组按两个实例分配宽度，避免整组被压缩成一个 tab 的宽度。保留右邻校验、整组移动、拖动取消和输入隔离，Escape 取消拖拽不传入 Vim。
5. 透明度只更新背景 CSS；终端外观 effect 只依赖终端主题、字体和字号，避免滑动或保存透明度引发字体加载、重新测量、resize 或重连。
6. 删除固定与自动隐藏 Hook、相关状态和无用的终端弹窗锁回调；旧应用主题、固定、最大化及折叠偏好退出读写，清理对应浏览器键，防止通用偏好合并重新带回旧字段。
7. 极窄标签逐级隐藏辅助标记并改用序号，完整实例名保留在可访问名称、鼠标提示和操作菜单中。320px 设置弹窗改用单列主题选项，保留内部滚动与固定操作区。

验证脚本同步适配了延迟连接与新版导航：默认字体检查在实际访问第二个终端后进行；滑条键盘检查等待弹窗过渡结束。保留字体、Vim、权限、分屏和历史恢复的功能断言。

## 使用与发布边界

- 顶栏会遮挡终端顶部少量内容，这是本次全高覆盖布局的明确选择；文字和图标不随背景一起降低透明度，选中与悬停提示仍保留。
- 手机同时显示大量 tab 时，等宽分配必然减小点击宽度；极窄 tab 显示序号，菜单显示全名。没有设置固定实例数量上限。
- 浏览器验证使用真实 Chromium，手机使用视口和触摸事件模拟，尚未覆盖实体手机及 Safari / Firefox。
- 旧终端设置缺少透明度字段时按 50% 读取。新增字段由严格校验的 Hub API 接收，因此发布时应配套更新 Hub 后端与前端资源；无需数据库表结构迁移。
- PTY 尺寸控制和历史恢复继续遵循 [TERMINAL_DATAFLOW_REVIEW.md](TERMINAL_DATAFLOW_REVIEW.md) 的共享终端及有界内存语义。
