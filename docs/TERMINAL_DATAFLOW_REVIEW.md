# 共享 PTY 尺寸与终端历史恢复

本报告保留数据流修复时的实现与验证记录。后续 Hub 菜单已移除“接管终端尺寸”，并将“刷新此终端”简化为“刷新”；自动尺寸策略及恢复协议继续有效，当前界面见 [TAB_MENU_REVIEW.md](TAB_MENU_REVIEW.md)。

## 原因与修复范围

| 原问题 | 归因 | 落地结果 |
| --- | --- | --- |
| 手机连接或刷新后，电脑终端变窄 | 单 PTY 共用一套行列数是现有会话模型；新连接直接取代控制端、各浏览器自行 fit 是设计缺陷；丢弃最后一次 resize、ioctl 失败仍确认新尺寸是 bug | 稳定所有权、刷新租约、显式接管；所有客户端按确认网格绘制，窄窗格内部滚动 |
| 刷新后只剩少量历史或一屏 | 单终端刷新重建渲染器，旧回放只取最多 512 KiB 原始控制流，浏览器默认仅 500 行；原始尾部不能表达完整终端状态，属于恢复方案的设计缺陷 | 软刷新保留渲染器；整页刷新恢复有界 VT 状态与历史；重连增量含尺寸顺序，默认最多 5000 行 |

## 行为与实现

两个项目共同修复：新客户端不抢占当前尺寸控制权；刷新恢复稳定浏览器身份；Hub 和直连客户端使用服务端确认的统一网格；窄窗口通过内部滚动查看。Hub 标签菜单增加“接管终端尺寸”，受连接状态、写权限及 GoTTY 能力控制。

“刷新此终端”现在仅重连 WebSocket，保留 xterm、滚动历史及其他窗格。整页刷新通过 GoTTY 服务端 VT 快照恢复普通/备用屏幕和保留历史。断线增量恢复使用有序事件，同时记录输出和 resize；xterm 解析完成后再提交恢复位置。历史解析期间抑制输入、查询回复、剪贴板和传输副作用。

Hub 网关转发协议版本、事件序号及随机浏览器身份；身份先绑定实际认证账号。共享核心升级至 `@gotty/terminal-core@0.4.0`，GoTTY 源码与 Hub vendor 包保持一致。

实时终端查询由一个浏览器响应。优先使用可见的尺寸控制端，断线或隐藏时使用最早的可见可写连接；不会为此转移尺寸租约。自动响应不触发用户输入活动；光标位置响应与实际查询关联，避免误拦截修饰功能键。

运行策略、配置和保留上限见 GoTTY 的 `docs/terminal-recovery.md`。状态仅存在于运行中的 GoTTY 内存，默认最多 5000 行，并受字节预算约束；不提供进程重启后的历史归档。图像及终端私有扩展不属于快照恢复目标。

## 整体 review 重点

- PTY ioctl 成功后才发布尺寸；只读、隐藏窗格、断线宽限和慢消费者退出遵循同一所有权逻辑。
- 输出、尺寸、快照切点在会话锁下排序；客户端在异步解析边界处理 resize 与恢复结束，避免旧输出在新尺寸下被解析。
- 恢复初始化等待旧输出解析完成；认证初始化发出前禁止 resize、输入和心跳抢先进入新连接。
- Hub 的查看状态和管理请求同样等待认证初始化，避免保留渲染器重连时先发查看消息导致握手失败。
- 快照区分真实行尾空格与空白单元格，保存软换行；备用屏幕不会污染普通历史。
- 影子终端查询不写入真实 PTY，不阻塞；历史内容不重新触发剪贴板、查询与文件传输。
- 历史、事件、客户端接收队列均有上限；恢复缺口转为完整快照，淘汰历史有可见提示。

Review 中补齐的边界：隐藏客户端退出 `median` 计算后会触发重新协调；`fixed` / `median` 不额外选举尺寸控制端；中断文件传输后软刷新重新启用可写终端的键盘输入；实时查询去重保留中文、方向键、修饰功能键及粘贴；中文和 emoji 在行尾换行时保留空白补位与真实空格的区别，历史裁剪保留宽字符的后续单元格，避免重排丢掉行尾字符。

没有遗留的阻断问题。保留边界是单 PTY 共享网格、进程内有界历史，以及 VT 快照对图片、私有扩展和部分较新 Unicode 字符宽度的限制。快照实现保留 MIT 许可及上游版本说明，后续升级须继续与真实 xterm 对比。
