# 用户名账号与 GoTTY 一步接入实施规划

日期：2026-11-09

状态：已实施并完成整体 review；验证记录见 [USERNAME_AUTH_REVIEW.md](USERNAME_AUTH_REVIEW.md)。

核对基线：GoTTY `9ab9247`；GoTTY Hub `8848bf5`。

## 1. 本轮决策

- 按全新数据结构实施，无旧账号、旧数据库、旧配置或旧客户端兼容任务。验收使用全新的数据目录。
- Hub 开放用户名和密码注册，注册成功即可登录；所有邮箱验证和 Resend 功能退出产品。
- GoTTY 接入表单只有 Hub URL、用户名两个输入项，一次提交完成注册及连接，无验证码、密码、管理令牌、确认绑定步骤。
- 使用普通密码注册和登录，输入框支持显示密码；数据库采用 Argon2id 哈希存储。按最终要求，管理员的原始密码单独保存到私有 config，普通用户密码不写入 config。
- 管理员用户名固定为 `admin`，由本机初始化创建；账号和实例授权统一使用用户 ID。

本文取代原实施规划、ADR-003 和管理员说明中的邮箱、验证码及手工填写本机 `.admin` 令牌流程。终端功能继续沿用现有实现：Hub 工作台集成 GoTTY 终端核心，Connector 直接连接当前共享 PTY。

## 2. 实施前的问题与改动原因

| 问题 | 已核对的代码事实 | 需要的调整 |
|---|---|---|
| Hub 按钮风格不一致 | `gotty/js/src/hub-manager.ts` 单独创建 Bootstrap 文本按钮；`top:12px;right:12px` 与连接数控件重叠 | 使用原有右上角小图标按钮样式与独立位置 |
| 配置输入过多 | 当前要求 URL、实例名、所有者邮箱、其他授权邮箱、本机令牌、验证码，分申请和确认两次提交 | 两项输入、单次绑定；实例名称自动生成 |
| 邮箱贯穿账号模型 | 用户主键、会话、实例归属、授权、偏好及管理员判断均依赖邮箱 | 建立干净的用户 ID 和 username 模型，统一调整查询及接口 |
| 启动仍依赖 Resend | `config.rs` 首次要求 API key、admin email；`main.rs` 启动邮件 worker | 固定管理员 `admin`，首次只输入密码，移除邮件配置及任务 |
| 当前注册可创建账号 | 邮箱 OTP 登录及绑定确认包含隐式创建用户逻辑 | 只有 Web 注册和本机管理员初始化可以创建用户，设备接入只能绑定已存在用户 |

## 3. Hub 账号、权限与首次启动

### 3.1 注册与登录

- 登录弹窗提供“登录 / 注册”切换，均填写用户名和密码；注册不增加确认密码或验证码步骤。
- 新用户名采用 3–64 位 ASCII 字母、数字、下划线、短横线和点，首字符为字母或数字；去除首尾空白并统一为小写，数据库唯一约束负责并发去重。
- 密码保持现有 12–256 字节限制，原样参与密码哈希，不自动去除空白；注册页明确显示规则。
- 注册成功建立正常会话，直接进入终端工作台。用户名已存在返回 `409 username_taken`，不能覆盖原账号。
- 登录失败统一返回 `401 invalid_credentials`，界面显示“用户名或密码错误”。
- 沿用 HttpOnly / SameSite Cookie、生产 Secure Cookie、CSRF、Origin 校验、限流及密码计算并发限制。
- 用户名只用于账号定位，不充当登录或终端连接凭据。设备注册不建立用户浏览器会话。

### 3.2 全新数据结构

- `users`：`id`、规范化且唯一的 `username`、非空 `password_hash`、`is_admin`、创建时间。
- `sessions`、`preferences` 关联 `user_id`；`instances` 关联 `owner_id`；`grants` 关联 `user_id`。
- 保留实例 ID、设备凭据摘要、授权版本、凭据轮换所需字段、终端票据与审计能力。
- 增加设备注册幂等记录，保存请求 ID、用户 ID、claim 摘要、实例 ID；不保存原始 claim 或设备凭据。
- 重新整理初始 schema，去掉 `challenges`、`outbox` 以及邮箱确认用 `enrollments` 表；保留轮换功能需要的结构。
- 用户、会话、实例和授权查询全部使用明确列名；终端网关的会话和授权复查同步改为用户 ID。

### 3.3 管理员与本机命令

- 管理员用户名固定为 `admin`，不能改名或公开注册。首次完全不带参数启动 binary，必须隐藏输入一次非空密码；空白值重新提示，无用户名输入或确认步骤。
- 在监听 Web 请求前完成管理员创建，避免管理员名称被公开注册抢先占用。Web 注册接口始终创建普通用户，忽略或拒绝管理员字段。
- 默认数据根目录为 `~/.gotty-hub`；`config` 为 `{"password":"原始管理员密码"}`，数据库保存密码哈希。目录权限为 `0700`，config 原子写入且权限为 `0600`；数据库、日志和升级文件默认也位于此目录。
- 自动化初始化支持 `gotty-hub [serve] --password VALUE`、`--password-stdin`；两参数互斥，优先级为“CLI > HUB_PASSWORD > config”。首次无参数引导不使用环境变量跳过输入。首次初始化保存有效密码；已有配置时启动覆盖不改写文件，`config` / `configure` 显式持久化。
- 每次启动按有效密码同步 `admin` 的数据库哈希；密码变化撤销旧会话。Web 修改管理员密码和本机重置同步保存 config，下次启动仍服从 CLI/环境覆盖。stdin 启动后的后台重启保留其有效覆盖，不重复读取管道。
- `check` 只检查配置和已初始化状态；独立的本机 `users reset-password --username USER` 命令通过隐藏输入或 stdin 设置密码并撤销该用户会话。
- Web 保留修改密码、退出当前会话和退出全部会话。忘记密码入口改为本机重置说明，管理员同样通过服务器本机重置恢复访问。
- 后台继续提供统计、升级、重启、日志；管理员身份由数据库账号标记判断。
- Dashboard 移除待投递邮件指标，改为离线实例数量。

### 3.4 实例授权

- 所有者、操作者、观察者角色继续保留；授权管理输入改为用户名，只能授权已注册账号。
- 实例访问依旧依据该用户的授权，普通账号和管理员后台权限分别检查。
- 更换密码、撤销会话和撤销实例授权仍使对应终端连接及时失效。
- 侧栏账号标题、账号弹窗、授权列表、中英文文案及演示数据统一使用用户名。

## 4. GoTTY 一次提交接入

### 4.1 用户操作

1. 在 Hub Web 使用用户名和密码注册账号。
2. 在已启用 Hub 功能的 GoTTY 右上角点击 Hub 图标。
3. 填写 Hub URL、用户名，点击“接入 Hub”。
4. GoTTY 在后台完成设备注册、私有文件保存和 Connector 连接；界面先显示“已注册，正在连接”，握手成功后显示“已连接”。

表单不包含实例名、授权用户、邮箱、验证码、Hub 密码或本机管理令牌。实例名采用“主机名 + 稳定短 ID”自动生成；授权用户在 Hub 实例详情中管理。打开配置时回显地址和用户名，并展示真实连接状态。

若用户名不存在，Hub 返回 `404 user_not_found`。GoTTY 显示：

> 该用户名尚未在此 Hub 注册，请先前往 Hub Web 注册，再重试接入。

错误旁提供前往已校验 Hub 地址的注册链接；Hub 支持 `?auth=register` 直接打开注册弹窗。GoTTY 保留已填内容，不创建空账号或无主实例。连接失败、地址不合法、限流、用户名不存在和保存失败分别给出可读错误。

### 4.2 设备注册与凭据

- GoTTY 后端调用新的 `POST /api/v1/instances/register`，发送 `username`、自动生成的 `name`、`request_id`、随机 `claim`。
- 用户 ID 必须来自已存在的账号；Hub 在同一事务中创建实例、所有者授权和幂等记录。
- 响应为 `instance_id`、高熵设备 `credential`、`protocol:1`。设备凭据只在 GoTTY 后端处理和落盘，不返回配置页面。
- claim 是内部随机持有秘密，用户无需输入、验证或确认；Hub 仅保存摘要，沿用现有设备凭据派生和摘要存储机制。
- 请求 ID 与 claim 在网络请求前私有持久化，重复提交、响应丢失或成功后保存失败可恢复同一次结果，不创建重复实例。
- 重试只恢复原注册结果；不能改写所属用户、恢复已解绑实例或绕过凭据轮换。
- Connector 仍使用实例 ID + 设备凭据进行 WSS 认证，用户名不是设备连接密码。
- GoTTY 本地管理接口收敛为一次提交 `URL`、`Username`；删除 `enroll` / `confirm` 双阶段动作及 pending 邮箱确认状态。
- 本地配置采用现有 0600 原子写入，保存失败保留可重试状态；管理网络请求继续不阻塞终端状态锁。

该模式允许任何知道用户名的人把自己控制的 GoTTY 注册给该账号；注册者不会因此获得该账号会话或其他实例权限。此行为符合“仅凭用户名接入”的要求。

### 4.3 GoTTY 主站管理权限

- 保留 `--hub-enabled` 显式开关，启用后显示 Hub 入口。
- 有 GoTTY 登录凭据时自动复用当前登录态；无登录密码且启用 Hub 时，主站访问者可配置绑定，权限策略与现有重启等管理功能一致。
- 所有公开分享入口均禁止查看和修改 Hub 管理配置，包括可写分享。
- 绑定写操作保留同源检查、JSON 请求限制和请求大小限制；移除 `.admin` 文件生成、请求头要求和表单输入。

这里调整的是无密码主站的管理策略，不能用“前端隐藏令牌”替代实际权限设计。

## 5. GoTTY 按钮和弹窗

- Hub 入口采用原有工具按钮的 28×28 尺寸、14px SVG、4px 圆角、半透明深色背景、悬停效果和图标颜色。
- 接在现有右侧操作按钮之后，统一间距并避让可选终端状态提示；连接数、显示设置、清理、上传、重启及分享入口均无重叠。
- 复用轻量通用按钮样式与位置规则，避免再次独立使用 Bootstrap 文本按钮。
- 提供“接入 GoTTY Hub”的 tooltip 和可访问名称，可用键盘聚焦、打开、提交和关闭。
- 保留配置弹窗，只有两项输入和一个接入主操作；请求期间防止重复提交，错误展示在表单内。
- 与现有 `gotty-panel-open` 事件协调，打开 Hub 配置时关闭显示设置或分享浮层；关闭后恢复焦点，表单按键不会进入终端。
- 真实连接状态独立展示；终端 favicon、Hub 标签状态点、侧栏状态点继续消费设备活动状态，离线仍使用断网 SVG。

## 6. 接口契约

| 接口 | 请求 / 行为 |
|---|---|
| `POST /api/v1/auth/register` | `{username,password}`；创建普通用户并建立会话 |
| `POST /api/v1/auth/password/login` | `{username,password}`；验证已存在用户后建立会话 |
| `GET /api/v1/me` | 返回 `id,username,csrf,hub_address,is_admin` |
| `PUT /api/v1/me/password` | 修改密码、撤销旧会话并返回新会话 |
| `GET/PUT /api/v1/instances/:id/grants` | 返回用户名与角色；写入 `{username,role}`，内部关联用户 ID |
| `DELETE /api/v1/instances/:id/grants/:username` | 按用户名定位授权后撤销，继续校验所有者权限 |
| `POST /api/v1/instances/register` | 设备单次注册，公开且限流，原子创建实例并支持幂等重试 |
| `GET/POST GoTTY -/hub` | 读取绑定摘要 / 提交两项配置，设备秘密始终留在后端 |

删除 OTP request/verify、邮件密码重置/预验证、邮箱申请/确认接口及其公开路由例外。新增公开接口逐一列入鉴权和限流规则，其他写接口继续要求用户会话及 CSRF。

## 7. 实施范围与顺序

| 顺序 | 落点 | 交付内容 |
|---|---|---|
| 1 | Hub `migrations/`、`config.rs`、`main.rs`、`security.rs` | 干净 schema、管理员初始化、用户名规则、账号注册和密码登录、会话关联、Resend 配置及邮件任务删除 |
| 2 | Hub `api.rs`、`gateway.rs`、`admin.rs` | 单次设备注册、用户名授权、用户 ID 查询、后台统计调整、密码重置命令 |
| 3 | Hub `frontend/src/main.tsx`、`api.ts`、`errors.ts`、`i18n.ts`、`Admin.tsx` | 注册登录界面、用户名展示和授权、接入说明、注册链接、无邮件恢复说明及错误文案 |
| 4 | GoTTY `server/hub.go`、`server/server.go`、相关选项说明 | 单步绑定、自动命名、结构化错误、幂等持久化、主站权限复用、移除额外管理令牌 |
| 5 | GoTTY `js/src/hub-manager.ts`、工具栏样式及嵌入资源 | 原风格图标、两个字段、一次提交、状态回显、未知用户注册链接、浮层与焦点协调 |

Hub 前端继续使用现有 BoardUI 组件、语义 token 和双语机制；GoTTY 使用现有终端页面风格。共享 terminal-core 无需改变认证方案。

实施时同步更新 README、API / OpenAPI、管理员及运维说明、原规划与 ADR 的相关决策、Compose 和环境变量示例。CI 改用新账号初始化夹具，保持现有自动构建及 Release 流程。

## 8. 验收与整体 Review

1. 全新目录首次无参数启动只要求固定账号 `admin` 的密码；无 Resend 配置也能完成初始化、启动和登录后台，非交互初始化、config 优先级及 stdin 启动后重启正确。
2. 任意用户在 Web 注册、登录、退出、修改密码和撤销会话成功；重复用户名、并发注册、错误密码、限流与管理员字段注入按契约处理。
3. 数据库只保存密码哈希；config 按要求私有保存原始 admin 密码，权限为 `0600`。日志和 API 响应不包含原始密码，普通用户密码不写入 config。
4. 未注册用户名接入失败，错误和注册链接正确，不产生用户或实例；Web 注册后在原 GoTTY 表单重试成功。
5. 只填 URL 和用户名即可接入，无邮件、验证码、管理令牌和第二次确认；网络重试、并发提交及本机保存失败不会产生重复实例或丢失恢复信息。
6. 有密码主站复用登录态，无密码主站按明确策略操作，分享页面及跨站写请求无法修改绑定。
7. 知道他人用户名只能注册新实例给该账号，不能登录其账号或打开其已有实例；授权、观察者只读、凭据轮换和解绑仍正确。
8. 真实 Hub + GoTTY 验证 PTY、文件、ASR、断线重连及状态同步；侧栏、标签、最大化和折叠交互回归通过。
9. GoTTY 图标风格、位置、弹窗焦点及窄屏显示通过浏览器检查；Hub 注册、登录和授权界面通过中英文及明暗主题检查。
10. Rust 格式、Clippy、单元测试，Go 测试与相关 race 检查，前端类型检查/测试/生产构建、共享核心校验和真实跨仓库集成通过；整体 review 核对所有活动代码、配置、页面和文档已完成邮箱机制清理。

以上范围已完成实施和验证。账号结构版本升为 `0.2.0`，在线升级拒绝安装低于当前版本的 binary。实现与验证阶段未执行提交、推送、发布 Release 或生产部署；详细验证结果和后续提交说明见 [整体 Review](USERNAME_AUTH_REVIEW.md)。
