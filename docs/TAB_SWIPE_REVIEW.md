# 触控板与触屏横滑切换终端：实现与 review

## 使用行为

Mac 和触屏设备默认启用“横向滑动切换标签”，其他桌面设备默认关闭，均可在“设置 → 终端设置”调整。以前显式保存的关闭选项仍然生效。选择按当前账号保存在此浏览器；不会随账号外观同步到其他设备。取消或保存失败保留原值，恢复默认采用设备默认值。站点存储被禁用时本次页面仍可使用调整后的值，但不能保证刷新后保留。

在 tab 行或终端内容区使用触控板双指横滑、触屏单指横滑，按当前排列切换相邻目标。触控板方向遵循系统滚动语义；触屏向左划进入下一个，向右划返回上一个。首尾不循环，离线标签仍参与导航。每次识别出的手势切换一次，切换后短暂显示目标名称；导航沿用现有激活逻辑，不直接请求修改终端尺寸。

触屏在抬起时切换，下一次触摸可以立即开始；点击标签和再次点击当前标签打开菜单的行为保留。开始移动前长按 250ms 则交给原来的排序或文字选择，不再解释为标签切换。

展开的分屏视为一个画面，例如 `A → [B | C] → D`，返回组合时恢复最后聚焦的成员，比例和左右顺序保持不变。窄屏收起分屏时按单个 tab 导航。

终端存在可横向滚动的内容时，内容区保留原生横向滚动；即使到达边界也不改为切换标签，可移到 tab 行滑动。上下滚动继续交给终端。菜单、弹窗、输入法组合输入、按住指针、标签/分隔条/文件拖拽期间不开始切换。带 Ctrl、Meta、Alt、Shift 的滚动和 Safari pinch 保留浏览器行为。

## 实现

- `frontend/src/workspace/swipe.ts`：独立识别器和相邻目标选择。初始横向分量至少为纵向的 2 倍，累计 80 CSS 像素提交。连续事件间隔达到 220ms 可重新开始；提交后经过至少 160ms，明确反向或惯性衰减后的明显重新加速也可启动下一次候选，仍需累计完整距离。持续或衰减的惯性不能仅凭时间重复切换。单次明确的反向或轴变化取消尚未提交的切换。
- `frontend/src/workspace/touchSwipe.ts`：独立触屏状态机。单指移动达到 12px 后判断方向，横向分量至少为纵向 2 倍才接管，抬起时净位移至少 80px 才切换。纵向、斜向、短移动、长按、取消、上下文变化均不提交。增加第二根手指后退出识别，直到下一次单指触摸。
- `frontend/src/workspace/useTabSwipe.ts`：在工作区公共容器使用捕获阶段、`passive:false` 的原生 wheel 监听，先于 xterm 的滚动和鼠标回传处理。像素、行、页单位归一化；明确横向意图后立即接管，达到距离阈值才切换。
- 事件开始时固定用途。纵向、歧义方向、横向内容滚动或不可取消的首事件，都不会在同一段事件中途改为标签切换。候选取消后的尾段仍被吞掉，避免输入落入新终端；只有成功提交的触控板手势允许通过重新加速/反向识别下一次手势。缩放和修饰键手势优先交还浏览器。
- 触屏在工作区捕获 `touchstart/touchmove`，在 document 捕获结束/取消和多指触摸。单指横滑接管时取消按钮的待完成按压，避免 React Aria 延迟点击误开菜单；标签栏移动仍送达 dnd-kit，让它取消尚未触发的长按排序。通过 document 的 `pointerdown` 记录开始时的菜单状态，避免“先关闭菜单，再把同一次触摸转成切换”。控件、选择中的文字、上传、IME 和拖拽不参与识别。
- 工作区上下文包含账号、当前实例、顺序、已打开实例、分屏状态。候选期间变化则取消，不选择过时的目标。导航复用 `activateInstance()`、现有 reducer、焦点恢复和工作区持久化；不刷新连接、重建 xterm 或清理历史。
- `frontend/src/workspace/interactionSettings.ts`：独立版本化浏览器设置，区分显式 false 与无设置，隔离账号、处理损坏/受限存储，监听同源浏览器标签页的设置变化，并拒绝旧账号的延迟保存。
- 设置使用现有 BoardUI Checkbox。外观保存成功后才提交本机手势选项，防止一次保存部分成功。没有数据库、GoTTY、共享终端核心或通信协议变更。
- 横向 overscroll 控制只在功能启用且有多个打开标签时生效，关闭时恢复 document 属性。监听器保留到卸载以处理已接管的尾段；卸载时移除监听器并清理定时器。

## 连续切换与触屏补充 review（2026-11-13）

Mac 连续切换迟缓属于手势边界识别缺陷：原实现把提交后的所有 wheel 事件视为同一段惯性，并由每个事件重新延后静默结束时间。第二次主动滑动也被吞掉，因而实际等待可能远大于 220ms。现实现保留惯性拦截，允许在衰减后的明显重新加速或明确反向时识别新候选，没有采用仅按冷却时间重复触发的办法。

移动端原先既不监听 TouchEvent，也默认关闭该选项，因此单指切换是能力缺失。本次增加独立触屏状态机并调整设备默认值；保留已保存的显式关闭选择。手机跟随桌面网格时通常存在横向内容溢出，此时应在顶部标签栏划动切换，内容区继续滚动终端；到滚动边界也不会突然改为切换。

整体 review 检查了惯性重入、取消后的事件所有权、双指加入、长按排序、菜单关闭时序、按钮延迟点击、控件与选区排除、账号及分屏状态变化、设置持久化、事件监听器清理。修正了菜单在 pointerdown 关闭后使同一次触摸意外进入切换的问题。触摸抬起时再次检查最终净位移、方向和工作区状态，避免提交已经回撤或过时的候选。未发现遗留阻断问题。

## 浏览器与硬件边界

触控板产生的标准 WheelEvent 没有手指数、可靠硬件类型、手指离开或惯性阶段信息，因此部分横向滚轮鼠标也可触发，连续手势的划分仍采用时间、方向与幅度启发式，不能精确复原系统手势阶段。直接触屏单指通过 TouchEvent 识别，多指交还浏览器，不实现多指切换。

自动验证运行于 Linux Chromium，CDP wheel 验证了真实浏览器与 xterm 的事件链路，不能替代 Mac 实体触控板或系统前进/后退手势验收。不可取消的初始事件会保留浏览器行为，不强行执行 Hub 切换。

Mac 后续真机验收应覆盖 Chrome、Edge、Safari、Firefox，自然滚动开/关，轻扫、长惯性、连续同向及反向滑动，首尾边界，双指缩放，以及已有浏览器前进/后退历史时的表现。触屏真机应覆盖 iOS Safari、Android Chrome、软键盘打开、长按排序、文本选择与浏览器边缘手势。方向和识别阈值如需调整，应以该硬件结果为依据。
